Where the CSV lives

After mining, artifacts land under:

Paths <kpms_root>/behavior_ethogram/grammar/seed_<seed>/
· candidate_sequences.csv — lean curation table
· candidate_exemplars.json — overlay match spans (verbose)

Mine command:

CLI uv run maze-mine-syllable-grammar-candidates --kpms-root … --seed … --manifest-path …

Knobs: --max-n 4 (longest bout n-gram), --min-count 5 (drop rare patterns). When stage_ii/bout_features.csv exists, mine auto-enriches pooled scalars and sets overlay flags.

What mine gives you (read-only columns)

pattern_json count n_trials mean_speed_mps must_review_overlay behavior_name anchor_bucket reviewed_at
[3, 7, 7] 842 61 0.09 1 you fill you fill you fill
[3] 1204 88 0.18 0 locomote moving
[12] 310 44 0.03 0 pause still

Discovery sort (how rows appear): count ↓, then pattern_len ↓. Subset patterns are not removed — [3] and [3,7,7] can both appear. Name long specific patterns first; short patterns are defaults (lesson 0002).

Curation loop
1. Mine → 2. Sort flagged rows (must_review_overlay=1) to the top → 3. maze-preview-grammar-candidate on exemplar matches → stamp reviewed_at → 4. Fill behavior_name + anchor_bucket → 5. maze-build-grammar-rules → export → evaluate vs is_moving anchor.

Columns you own

ColumnYour job
behavior_name Portable ethology string (groom, rear, …). Empty rows are skipped at build.
anchor_bucket moving | still | ignore — harness tag, one bucket per name.
reviewed_at ISO timestamp after you watched an overlay clip (required when must_review_overlay=1).
reviewed_trial_key Optional audit trail — which exemplar trial you reviewed.
notes Freeform — subset/superset reminders, pose notes, etc.

anchor_bucket cheat sheet

BucketWhen to useHarness
movingLocomotion, traversalScores vs is_moving anchor
stillPause, freeze, low displacementScores vs is_moving anchor
ignoreGroom, rear, pose-shaped stillExported but excluded from anchor agreement

Build fails if the same behavior_name gets two different buckets. Pose-shaped classes usually need ignore until finer anchors exist — scalars alone cannot separate groom vs rear.

When must_review_overlay = 1?

Auto-flagged when matches hit ambiguous bouts, speed gray zone (~0.06–0.14 m/s), or low speed + high |dheading|. Drag the simulator — thresholds match grammar_contract.py.

Preview before you name

For row i, match j in candidate_exemplars.json:

CLI uv run maze-preview-grammar-candidate … --row-index 0 --match-index 0 --out …/grammar_review/
Multiple: --match-index 2,3,4 or --random-matches 6 --match-seed 0 (directory --out)

Clips the pose overlay to the matched bout span ± 1 s. Watch → assign behavior_name → set reviewed_at (e.g. 2026-07-06T14:30:00).

Build gates (what blocks you)

  • Named row missing anchor_bucket → build error
  • must_review_overlay=1 and empty reviewed_at → build error (--force overrides)
  • Conflicting anchor_bucket for same behavior_name → build error
  • No rows with both name and bucket → build error

Successful build writes grammar_rules.json with priority = len(pattern) × 10 per rule — tying apply precedence to pattern length.
